# اتصال دامنه و گواهی HTTPS

این امکان برای **یک دامنهٔ عمومی هم‌زمان** و گواهی رایگان Let’s Encrypt با تأیید HTTP-01 است. به ثبت دستی کد، بارگذاری یا جابه‌جایی فایل گواهی نیازی نیست. فایل‌های لازم برای کلاینت ACME همراه برنامه هستند؛ سرور برای صدور و تمدید به اینترنت نیاز دارد.

## پیش‌نیازهایی که بیرون از برنامه تنظیم می‌شوند

1. مالک یک دامنهٔ عمومی باشید. در پنل شرکت دامنه، رکورد A نام انتخابی (برای نمونه `app.example.com`) را به **IP عمومی** شبکهٔ سرور وصل کنید. اگر رکورد AAAA دارید، IPv6 آن هم باید به سرور صحیح برسد؛ رکورد اشتباه می‌تواند صدور را ناموفق کند. اعمال تغییرات DNS ممکن است زمان ببرد.
2. دسترسی TCP پورت **۸۰** و **۴۴۳** از اینترنت تا این سرور برقرار باشد؛ برای سرور پشت مودم/روتر، هدایت پورت‌ها و در صورت لزوم مجوز فایروال شبکه یا ارائه‌دهندهٔ سرور لازم است. IP داخلی مانند `192.168.x.x` به‌تنهایی IP عمومی نیست. اینترنت اشتراکی یا CGNAT ممکن است مانع دریافت اتصال ورودی شود.
3. برنامه باید روی پورت ۸۰ اجرا شود و پورت ۴۴۳ آزاد باشد. برنامه سرویس دیگری را متوقف نمی‌کند. در نصب استاندارد ویندوز، سامانه با حساب SYSTEM اجرا می‌شود و پس از شروع شنود HTTPS، قاعدهٔ اختصاصی پورت ۴۴۳ در Windows Firewall را ایجاد یا فعال می‌کند. DNS، روتر و فایروال خارج از ویندوز را نمی‌تواند خودکار تنظیم کند.
4. **در معرض اینترنت قرار گرفتن سامانه، ورود کاربران را برای عموم قابل دسترس می‌کند.** برای همهٔ حساب‌ها رمز قوی و متفاوت انتخاب کنید و در صورت امکان دسترسی شبکه را محدود کنید. پیش از دریافت گواهی، HTTP فعلی رمزگذاری نشده است؛ از شبکهٔ مطمئن برای ورود مدیر استفاده کنید.

## فعال‌سازی

۱. از حساب مدیر وارد «تنظیمات سیستم» شوید. در بخش **دامنه و گواهی HTTPS** نام کامل دامنه را بدون `https://`، پورت یا مسیر وارد کنید. دامنهٔ داخلی، آدرس IP و wildcard پشتیبانی نمی‌شوند.

۲. ایمیل اطلاع‌رسانی اختیاری است؛ اگر وارد شود در حساب Let’s Encrypt ثبت می‌شود. رمز فعلی مدیر را وارد کرده و با آگاهی از عمومی‌شدن دسترسی، شرایط Let’s Encrypt را بپذیرید. «دریافت و فعال‌سازی HTTPS» را بزنید.

۳. وضعیت همان بخش را تا پایان بررسی کنید. تأیید مالکیت ممکن است چند دقیقه طول بکشد. فعال‌شدن وضعیت یعنی گواهی روی سرور نصب شده است؛ آن را با مرورگر در `https://نام-دامنه` و از یک شبکهٔ بیرونی نیز امتحان کنید. در صورت نیاز دوباره وارد شوید. اگر خطا دیدید، DNS، دسترسی از اینترنت، خروجی اینترنت سرور و آزادبودن پورت ۴۴۳ را بررسی و پس از رفع مشکل دوباره تلاش کنید. محدودیت تعداد درخواست‌های Let’s Encrypt ممکن است اعمال شود؛ پشت سر هم درخواست تکراری ندهید.

## رفتار و نگهداری

- پس از فعال‌سازی، درخواست HTTP همان دامنه به HTTPS هدایت می‌شود؛ نشست HTTPS ویژگی `Secure` دارد. HTTP از آدرس‌های عمومی دیگر پذیرفته نمی‌شود. **برای سازگاری، HTTP با IP داخلی همچنان مجاز و بدون رمزگذاری است**؛ برای محرمانگی همهٔ کاربران از دامنهٔ HTTPS استفاده کنند. اگر روتر یا پراکسی نشانی کلاینت اینترنتی را به آدرس داخلی تبدیل می‌کند، برنامه نمی‌تواند آن را از شبکهٔ داخلی تشخیص دهد؛ در مرز شبکه دسترسی HTTP را محدود کنید.
- برنامه هر ۱۲ ساعت وضعیت را بررسی و در ۳۰ روز آخر اعتبار برای تمدید اقدام می‌کند. برای تمدید خودکار، سرور روشن و اتصال اینترنت، DNS صحیح و پورت ۸۰ برقرار باشند. اگر تمدید ناموفق شود، گواهی قبلی تا انقضای آن حفظ می‌شود و خطا در بخش تنظیمات دیده می‌شود.
- تغییر دامنه با وارد کردن نام جدید انجام می‌شود. تا دریافت و فعال‌شدن گواهی جدید، گواهی قبلی حفظ می‌شود؛ پس از موفقیت، دامنهٔ قبلی دیگر گواهی فعال این سامانه نیست.
- گواهی و کلید خصوصی در `C:\BabolToyor\data\tls\state.json` نگهداری و پوشه در ویندوز به SYSTEM و Administrators محدود می‌شود. به کلید دسترسی عمومی ندهید. بستهٔ برنامه شامل کلید واقعی شما نیست. پشتیبان SQLite برنامه **شامل گواهی و کلید نیست**؛ در صورت پشتیبان‌گیری جداگانه از پوشهٔ `data/tls`، آن را محرمانه نگه دارید. ارتقای استاندارد پوشهٔ داده را حفظ می‌کند.
- در صورت خرابی فایل گواهی یا اشغال بودن پورت پس از راه‌اندازی مجدد، وضعیت خطا نمایش داده می‌شود و HTTP عمومی به‌جای بازگشت بی‌صدا به حالت ناامن مسدود می‌ماند؛ از شبکهٔ داخلی به تنظیمات مراجعه کنید.

این قابلیت با گواهی عمومی روی اینترنت طراحی شده است؛ برای شبکهٔ کاملاً داخلی یا wildcard نیاز به روش تأیید دیگری است که این نسخه ارائه نمی‌دهد.
