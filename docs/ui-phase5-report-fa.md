# فاز ۵ (بخش الف) — یکسان‌سازی توکن‌ها: حذف نسل‌های مردهٔ پالت

**نسخه:** ۱.۱.۱۰ / `37.6.0` (بدون تغییر شماره نسخه) · **شاخه:** `arena/6f0ff475-btsmart`
**دامنه:** فقط `public/styles.css`، `public/design.css`، `public/theme.css` و ابزار `scripts/verify-css-cascade.js`.

---

## ۱) یافته: چهار نسل پالت روی هم انبار شده بود

در فاز ۴ ثابت شد لایه‌های CSS روی هم «لایه‌روی» شده‌اند. همین موضوع دربارهٔ **متغیرهای رنگ** هم درست بود:

```
styles.css  (:root #1)  --brand:#b40f23  --ink:#1c222b  --muted:#6f7a87  --line:#e2e6eb   ← نسل اول
styles.css  (:root #2)  --brand:#b3132a  --ink:#171b21  --muted:#737c88  --line:#e5e7eb   ← نسل دوم (v21)
design.css  (:root)     --brand:#b40f23  --ink:#151a21  --muted:#67707d  --line:#e6e9ee   ← نسل سوم
theme.css   (:root)     --brand:var(--bt-brand)  --ink:var(--bt-ink)  …                    ← نسل چهارم: alias روی --bt-*
```

یعنی از سه نسل اول، **هیچ‌کدام امروز مؤثر نیستند**؛ `theme.css` (آخرین فایل) هر سه را با alias روی توکن‌های `--bt-*` بازنویسی می‌کند. آن تعریف‌ها فقط سردرگمی می‌ساختند (هر کس رنگی را عوض می‌کرد، سه جای دیگر دست‌نخورده می‌ماند).

## ۲) کار انجام‌شده

همان قاعدهٔ فاز ۴، این بار روی **متغیرهای سفارشی**: نام متغیر هم یک ویژگی است و آبشاری می‌شود؛ اگر بعد از یک تعریف، تعریف دیگری با همان `(media, selector, --name)` بیاید، اولی مرده است.

| فایل | خطوط حذف‌شده | توضیح |
|---|---:|---|
| `styles.css` | ۱۹ | دو بلوک `:root` قدیمی (نسل اول و دوم) |
| `design.css` | ۱۸ | پالت نسل سوم |
| `theme.css` | ۴ | تکرارهای درون‌فایلی (`--bt-rail-bg`، `--bt-rail-text`، `--font`) |

- **۶۶ اعلان متغیر** با **۳۹ نام** حذف شد (در ۴۳ خط).
- حجم CSS: **۷۶۲٬۶۰۱ → ۷۶۱٬۱۰۷ بایت** (−۱٬۴۹۴).
- منبع واحد حقیقت حالا فقط `:root` در `theme.css` است؛ نام‌های قدیمی (`--brand`، `--muted`، `--line`، `--ink`، `--font`، `--r`، `--rail`، …) از طریق alias باقی می‌مانند، پس **۱٬۵۵۸ استفاده از ۹۸ نام غیر `--bt-*` در CSS/JS دست‌نخورده** کار می‌کند.

## ۳) اثبات

ابزار `scripts/verify-css-cascade.js` حالا **متغیرهای سفارشی را هم** در نقشهٔ آبشاری می‌آورد و مقایسهٔ خود را روی «متن اعلان برنده» انجام می‌دهد (بدون هیچ نرمال‌سازی؛ سخت‌گیرانه‌ترین حالت):

```json
{
 "declarations": { "before": 22057, "after": 21991 },
 "cascadeKeys":  { "before": 21969, "after": 21969 },
 "rules":        { "before": 6799,  "after": 6799  },
 "differences":  { "missing": 0, "changed": 0, "added": 0, "orderProblems": 0 }
}
```

آزمون خودِ ابزار: با تغییر یک کاراکتر در `--bt-brand`، ابزار خطا داد (`✖ نقشهٔ آبشاری تغییر کرده است`)، پس صرفاً «همیشه سبز» نیست.

## ۵) چه چیزی هنوز مانده (بخش ب)

۱. **کاهش `!important`های برنده:** ۳٬۹۶۹ مورد (۱٬۵۲۲ در `compatibility.css`، ۱٬۲۵۷ در `theme.css`، ۴۷۲ در `form-layout.css`). این کار بدون مرورگر واقعی قابل اثبات نیست؛ چون انتخابگرها روی عناصر هم‌پوشان می‌نشینند و ویژگی (specificity) تنها با رندر معلوم می‌شود.
۲. **۷ اعلانی که برای تست‌های متنی نگه داشته شد** (فهرست در گزارش فاز ۴) — با مهاجرت آن ۵ تست به «نقشهٔ آبشاری» آزاد می‌شوند.
۳. **۵ کاندید یکسان‌سازی کوچک** که هنوز انجام نشده (`--v26-surface`، `--v26-ink`، `--v26-radius-sm`، `--fx-radius`، `--shadow-xs`): هر کدام یک‌بار تعریف شده‌اند و مقدارشان دقیقاً برابر یک توکن `--bt-*` است؛ تبدیلشان به alias بی‌خطر است ولی چون هر کدام یک مصرف‌کنندهٔ انگشت‌شمار دارند، در فاز بعد همراه با بقیه انجام می‌شود.
