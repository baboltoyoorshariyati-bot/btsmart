# بریف آمادهٔ سپردن به هوش مصنوعی دیگر — بازطراحی رابط کاربری «بابل طیور»

> این فایل را کامل کپی کنید و به همراه لینک‌های انتهای صفحه به هوش مصنوعی موردنظر بدهید. همهٔ اعداد و اندازه‌ها از اندازه‌گیری واقعی همین پروژه گرفته شده‌اند.

## ۱) پروژه در یک پاراگراف

یک سامانهٔ عملیات داخلی فارسی و راست‌به‌چپ (RTL) برای شرکت توزیع مرغ: کارتابل‌های نگهبانی، فروش، انبار (وزن‌کشی و نوبت‌های ناخالصی)، ترابری/پخش، فروشگاه، تسویه و مدیریت. کلاینت یک اپلیکیشن تک‌صفحه‌ای است (Vanilla JS + چند فایل CSS) که روی یک سرور محلی ویندوز اجرا می‌شود و کاربران آن اپراتورهای انبار/فروش با مانیتورهای کوچک (۸۰۰×۶۰۰) و گوشی موبایل هستند.

## ۲) مسئله‌ای که باید حل شود

رابط کاربری در موبایل و دسکتاپ کوچک «شلوغ و ناجور» است. اعداد واقعی وضعیت فعلی:

| موضوع | وضعیت فعلی |
|---|---|
| ردیف‌های فهرست کارتابل | عرض ثابت **۱۱۰۶ تا ۱۲۳۳px** در همهٔ عرض‌ها (حتی ۳۷۵px)؛ به‌خاطر `width:max-content` و `flex-wrap:nowrap` و `min-width` سلول‌ها |
| اسکرول افقی | صفحه `overflow-x:hidden` است؛ فقط هر فهرست نوار افقی ۸ پیکسلی داخلی دارد |
| هدر | **۱۳۳px** در ۸۰۰×۶۰۰ (۲۵٪ ارتفاع دید) |
| دکمه‌ها | ارتفاع **۳۰ تا ۳۲px** در دسکتاپ کوچک (زیر حد لمس ۴۴px) |
| تایپوگرافی | در برگهٔ آماده‌سازی ۲۳ عنصر ۱۲px و ۷ عنصر ۱۰px |
| راهنماها | بلوک ۵ خطی در برگهٔ انبار؛ در فرم فروش پاراگراف ۵۳px دربارهٔ کلیدهای `Insert`/جهت‌دار که در موبایل بی‌معنی است |
| فرم سفارش | ارتفاع **۱۹۶۱px** (≈۳ صفحهٔ موبایل) بدون نشانگر مرحله |
| دکمهٔ نهایی | در ارتفاع واقعی ۵۲۰px، **۴۷۰px** زیر خط دید |
| نوار پیام (toast) | پایین صفحه و روی دکمه‌های آخر می‌افتد |
| ناوبری | ریل ۶۸px با برچسب‌های سه‌خطی در دسکتاپ کوچک |

## ۳) قواعد سخت (نقض نشوند)

1. **فقط لایهٔ نمایش.** چینش، اندازه، رنگ، اولویت دکمه‌ها. منطق کاری، محاسبهٔ وزن/ناخالصی، مجوزها، گردش سفارش و API **نباید** تغییر کند.
2. **RTL و فارسی.** همهٔ چیدمان‌ها راست‌به‌چپ؛ ارقام فارسی در نمایش، ورودی عددی `direction:ltr` و `inputmode="decimal"`.
3. **فونت موجود پروژه:** Vazirmatn (`/public/fonts/Vazirmatn-Variable.woff2`). فونت جدید اضافه نشود.
4. **بدون فریم‌ورک.** HTML/CSS خالص (بدون React/Tailwind build). CSS باید با لایهٔ موجود (`public/*.css`) سازگار باشد.
5. **سه بریک‌پوینت، نه بیشتر:** ≤۵۹۹ (موبایل) / ۶۰۰–۱۰۲۴ (دسکتاپ کوچک) / ≥۱۰۲۵ (دسکتاپ).
6. **دسترس‌پذیری:** هدف لمس ≥۴۴px زیر ۶۰۰px، متن ≥۱۳px، کنتراست ≥۴٫۵:۱، `:focus-visible` روشن، `aria-label` برای دکمه‌های آیکونی.
7. **کارایی:** بدون کتابخانهٔ جدید، بدون فونت اضافی، حجم CSS اضافه کمتر از ۳۰KB.

## ۴) سیستم طراحی پیشنهادی (قابل تغییر، ولی سازگار بماند)

| گروه | مقدار |
|---|---|
| فاصله | ۴ / ۸ / ۱۲ / ۱۶ / ۲۴ |
| گردی | ۱۰ (کنترل) / ۱۴ (کارت) / ۹۹۹ (چیپ) |
| متن | ۱۱ برچسب، ۱۲ کمکی، ۱۴ متن، ۱۶ ورودی/عنوان کارت، ۲۰ عنوان صفحه |
| ارتفاع کنترل | ۴۴px لمسی، ۳۸px ماوس |
| رنگ | برند `#b40f23`، متن `#1d2733`، کمکی `#6b7684`، خط `#e3e8ee`، زمینه `#f4f6f8`، موفق `#0f7a4d`، هشدار `#8a5a00`، اطلاع `#12508f`، خطر `#b42318` (هر کدام با پس‌زمینهٔ ۵٪) |
| ثابت‌ها | هدر ۵۶px، تب‌بار موبایل ۵۶px، ریل دسکتاپ ۷۲px، نوار عملیات چسبان با احتساب `safe-area` |

## ۵) الگوهای موردنیاز (خروجی مورد انتظار)

1. **کارت صف سفارش:** خط ۱ نام مشتری + چیپ وضعیت؛ خط ۲ سه جفت «برچسب: مقدار»؛ خط ۳ یک دکمهٔ اصلی تمام‌عرض + دکمهٔ «⋯» برای عملیات فرعی.
2. **نوار عملیات چسبان:** یک دکمهٔ اصلی + یک دکمهٔ ثانویه، همیشه در دید (موبایل: بالای تب‌بار).
3. **راهنمای یک‌خطی:** متن کوتاه + لینک «راهنما» که متن کامل را باز می‌کند.
4. **ورودی وزن:** ورودی عددی ۴۴px با واحد کنارش، چیپ «۲ نوبت ثبت‌شده»، دکمهٔ «ناخالصی» (پنجرهٔ ناخالصی فعلی حفظ شود).
5. **جدول → کارت:** زیر ۹۰۰px جدول‌های پهن (فاکتور، سوابق، تخصیص) به کارت با چهار فیلد کلیدی + «جزئیات» تبدیل شوند.
6. **فرم گام‌دار:** گام‌های شماره‌دار با هدر جمع‌شونده؛ گام فعال باز، بقیه بسته با خلاصه.
7. **هدر و ناوبری:** هدر ۵۶px (عنوان + ۳ آیکون)؛ موبایل تب‌بار ۵ آیتم؛ دسکتاپ کوچک ریل ۷۲px آیکونی با برچسب یک‌خطی.

## ۶) صفحه‌هایی که باید بازطراحی شوند

| صفحه | نکتهٔ کلیدی |
|---|---|
| کارتابل انبار (ورودی / آماده‌سازی / تحویل‌شده) | کارت صف + نوار عملیات |
| برگهٔ آماده‌سازی و وزن‌کشی | راهنمای یک‌خطی، ورودی درشت، چیپ نوبت، نوار چسبان |
| فروش: سفارش غیرحضوری و حضوری | سه گام + صف تلفنی کارتی |
| تسویه و فاکتورها | جدول → کارت + یک دکمهٔ پرداخت |
| نگهبانی (ورود/خروج) | دو بخش «وسیله» و «مراجعه»، ورودی پلاک سه‌کادری |
| مدیریت (سوابق، کاربران، گزارش‌ها) | جدول تطبیقی + فیلتر جمع‌شونده |
| سند انبار (مودال) | امروز خوب است؛ فقط تمام‌صفحه در موبایل + نوار چاپ چسبان |

## ۷) معیار پذیرش

1. در ۳۷۵×۶۶۷، ۸۰۰×۶۰۰، ۱۰۲۴×۷۶۸ و ۱۴۰۰×۹۰۰ هیچ عنصری در محتوا عرضش از کادرش بیشتر نباشد (بدون اسکرول افقی).
2. حداکثر **یک** دکمهٔ اصلی در هر نما.
3. دکمهٔ اصلی هر صفحه همیشه در دید (sticky) و ≥۴۴px در لمسی.
4. هیچ متن نمایشی زیر ۱۱px و هیچ متن بدنه زیر ۱۳px.
5. نوار پیام با هیچ دکمه‌ای هم‌پوشانی نداشته باشد.
6. هدر ≤۶۴px.

## ۸) خروجی که از هوش مصنوعی می‌خواهیم

- یک فایل `ui-compact.css` (یا مجموعه قواعد CSS) که در انتهای لایهٔ استایل پروژه اضافه شود و الگوهای بالا را پیاده کند.
- برای هر صفحه: ساختار HTML پیشنهادی (کلاس‌ها) بدون تغییر شناسه‌ها/داده‌های فعلی.
- توضیح کوتاه هر تغییر + دلیل، به فارسی.
- جدول «قبل/بعد» با اعداد (عرض ردیف، ارتفاع هدر، ارتفاع دکمه).
